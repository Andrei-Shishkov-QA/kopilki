# Как устроены «Копилки» — простыми словами

Обновлять этот файл при каждом изменении устройства (правило 9 в CLAUDE.md).
Последнее обновление: 27.11.2026, версия 1.1.0.

## 1. Из чего состоит система

```
Телефон папы ─┐                                    ┌─ GitHub (код, история, выкладка)
Телефон мамы ─┼── сайт (GitHub Pages) ── браузер ──┤
Компьютер    ─┘         │                          └─ Firebase (вход + база данных)
                        └ копия данных на каждом устройстве
```

| Что | Где | Зачем | Кто управляет |
|---|---|---|---|
| **Код** | GitHub, репозиторий `Andrei-Shishkov-QA/kopilki` (публичный) | Вся программа и её история; любую версию можно вернуть | владелец (вход в GitHub), Claude — через приложение Claude на GitHub |
| **Сайт** | GitHub Pages: `andrei-shishkov-qa.github.io/kopilki/` | Страница, которую открывают телефоны | собирается сам из кода (GitHub Actions) |
| **Вход** | Firebase Authentication, проект `kopilki` | Пускает только семейный аккаунт (почта + пароль) | владелец (консоль Firebase) |
| **Данные** | Firebase Firestore, проект `kopilki` | Общий журнал записей для всех телефонов | владелец; правила доступа — `firestore.rules` |
| **Копия на устройстве** | браузер телефона (IndexedDB Firestore + localStorage) | Работа без интернета, быстрый старт | автоматически |
| **Резервные копии** | файлы `kidbank-ДАТА.json` у вас на телефоне/компьютере | Восстановить всё, если с Firebase беда | вы, по кнопке; приложение напоминает |

Платить сейчас не нужно ни за что: GitHub Pages и Firebase (тариф Spark) бесплатны.

## 2. Главная идея: журнал записей
- В базе хранится **только журнал** — список записей «что произошло»: фишка, прокол, покупка, итоги недели, изменение настроек и т. д.
- **Копилки, банк, фишки недели, история — нигде не хранятся.** Каждое устройство само пересчитывает их из журнала (движок, `src/engine`). Поэтому все устройства всегда видят одно и то же.
- Записи **только добавляются**. Ошибка исправляется новой записью: `void` (отменить запись) или `edit` (исправить поля). Отмену тоже можно отменить. Так ничего нельзя потерять.
- Правила базы (`firestore.rules`) это закрепляют: менять и удалять записи нельзя никому.

### Одна запись
```
{ id, seq, type, at, by, device, ...поля записи }
id     — уникальный номер (время + устройство + случайное)
seq    — порядок записи
type   — вид записи (см. ниже)
at     — когда, местное время с поясом: 2026-11-27T14:05:00+04:00
by     — кто записал: papa / mama
device — с какого телефона
```

### Виды записей (type)
| type | Что значит |
|---|---|
| `setup` | стартовая настройка и остатки |
| `config` | изменение настроек (деньги, доли, лимиты, цвета, вид, каникулы) |
| `balance_set` | остатки копилок вписаны вручную |
| `chip` | фишка (или итог дня дневной привычки, если `evening`) |
| `miss` | прокол дневной привычки (гаснет солнышко) |
| `income` / `spend` | деньги пришли / покупка за его деньги |
| `advance` | аванс в понедельник |
| `withdraw_request` | заявка на снятие из банка |
| `transfer` | переложить между копилками |
| `goals_set` | цели Сергея |
| `habit`, `habit_note` | привычка и её листок |
| `note`, `note_resolve` | заметка и её разбор |
| `doc` | тексты: «Как пользоваться», правила копилок |
| `session` | итоги недели (закрывают неделю) |
| `backup` | отметка «копия сохранена» (для напоминания) |
| `void`, `edit` | отменить / исправить запись |

**Совместимость:** новые версии могут только добавлять новые виды записей и поля. Старая версия незнакомые записи пропускает и показывает плашку «есть записи из новой версии».

## 4. Версии и выкладка
- **Ветки:** `beta` — новое, им пользуется владелец; `main` — для всех.
- **Адреса:**
  - `…/kopilki/` — основная (из `main`)
  - `…/kopilki/beta/` — бета (из `beta`)
  - `…/kopilki/v/1.1.0/` — каждая выпущенная версия (из веток `release/1.1.0`), остаётся навсегда
  - `…/kopilki/versions.json` — список выпущенных версий для приложения
- **Как выкатывается:** push в `main`, `beta` или `release/…` → GitHub Actions «Тесты» → если зелёные, «Публикация» (запускается от main) собирает все три вида адресов и публикует. 2–3 минуты.
- **Выпуск для всех:** владелец говорит «выкатываем» → номер в `src/version.js` → merge `beta` → `main` → ветка `release/X.Y.Z` с того же коммита. Ветки `release/*` никогда не менять и не удалять.
- **Откат в приложении:** «Ещё → Версия» → выбрать основную, бету или прошлую версию. Выбор запоминается на этом устройстве: основной адрес сам перебрасывает на выбранную версию. На старой версии сверху плашка «вернуться на последнюю».
- **Откат для всех:** `git revert` в `main` → через 1–2 минуты у всех прежняя версия.
- **Все версии работают с одной и той же базой** — поэтому важна совместимость журнала (раздел 2).

## 5. Вход и доступ
- Firebase Authentication, способ «Email/Password». Один **семейный аккаунт** (создаётся в консоли: Authentication → Users → Add user).
- После входа на телефоне выбирается **кто записывает** (папа/мама) — это поле `by` в записях. Хранится на телефоне.
- `firestore.rules`: читать и добавлять записи может только почта семейного аккаунта (вписана в правила в консоли). Изменять и удалять — никто.
- В консоли Firebase → Authentication → Settings → Authorized domains добавлен `andrei-shishkov-qa.github.io`.
- **Подключить новый телефон:** открыть сайт → войти почтой и паролем семьи → выбрать «папа/мама». Для удобства — «Поделиться → На экран Домой».

## 6. Где хранится что на устройстве (localStorage)
| Ключ | Что |
|---|---|
| `kidbank.user` | кто записывает на этом телефоне |
| `kidbank.cache` | последняя полная копия журнала (быстрый старт) |
| `kidbank.palette` | цвета |
| `kidbank.admin` | режим настройки включён (на 2 часа) |
| `kidbank.channel` | выбранная версия: пусто = основная, `beta`, `v/1.1.0` |
| `kidbank.device` | номер устройства |
| sessionStorage `kidbank.demo` | демо-записи (стираются при выходе из демо) |
| sessionStorage `kidbank.sessionDraft` | черновик итогов недели |
Firestore сам держит копию базы в IndexedDB — без интернета всё видно, записи отправятся сами.

## 7. Резервные копии
- Кнопка «Ещё → Сохранить копию» — файл со всем журналом. «Загрузить копию» — добавляет недостающие записи, ничего не удаляет.
- После итогов недели приложение предлагает сохранить копию. Если копию не сохраняли больше 7 дней — на главной плашка с кнопкой. Отметка о сохранении — запись `backup` (видна обоим телефонам).
- **Копии хранить вне репозитория** (он публичный). Рекомендуемая папка на компьютере: `Documents\kopilki-backups`.

## 8. Ограничения бесплатных тарифов
- Firestore Spark: 50 000 чтений/день, 20 000 записей/день, 1 ГБ. Каждое открытие после долгого перерыва читает весь журнал. Через ~год понадобится архив старых недель (IDEAS.md).
- GitHub Pages: сайт только из публичного репозитория; до 1 ГБ, 100 ГБ трафика/мес.

## 9. Если надо передать работу другой нейросети или человеку
Всё нужное — в репозитории: код, правила (CLAUDE.md / AGENTS.md), устройство (этот файл), идеи (IDEAS.md). Дать доступ к GitHub и (при необходимости) к консоли Firebase. Данные — в Firebase и в ваших файлах копий.

## 10. Будущий платный сервис (направление C)
Сейчас одна семья = вся база (`ev` в корне). Для многих семей журнал переедет в `families/<id>/ev`, имя ребёнка, люди и валюта — в настройки семьи, правила — «только члены своей семьи». Новый код пишется так, чтобы этот переезд был простым.
